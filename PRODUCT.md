# Product

## Register

brand

## Users

Developers and self-hosters evaluating an autonomous agent for their own machine.
The website explains capabilities and installation; the Telegram surface serves
operators following real work on a small screen.

## Product Purpose

Talos lets a model propose work while a deterministic permission kernel judges
every effect. The website should make that workflow understandable and testable.
The chat should distinguish work in progress, an approval request and an actual
result without asking the operator to interpret internal protocol text.

## Brand Personality

Bronze, watchful, capable. The existing guardian identity, sigil and warm amber
palette remain recognizable. The requested evolution adds personality, useful
emoji and clearer live feedback without theatrical claims about intelligence.

## Anti-references

Do not turn the site into an unreadable terminal costume. Avoid crowded navigation,
low-contrast body copy, blocking introduction animations, invented confidence scores,
fake live telemetry, and superiority claims unsupported by comparative tests.

## Design Principles

- Show the workflow and the evidence behind a result.
- Give the current state a clear visual priority.
- Preserve the existing brand, routes and public documentation.
- Keep operator identity, credentials and infrastructure out of public examples.
- Make optional capabilities and demonstrations explicit.

## Accessibility & Inclusion

Preserve the existing reduced-motion behavior and semantic controls. Improve
keyboard focus, narrow-screen navigation, contrast and touch targets. Status must
be understandable from text as well as color or emoji. No conformance certification
is implied by these implementation goals.
