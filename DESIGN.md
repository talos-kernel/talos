# Talos visual system

## Scene

An operator checks a job on a phone beside a laptop during an evening work session;
warm, legible surfaces should expose the next action without the glare or visual
noise of the current CRT overlays.

## Identity

Keep the bronze sigil and ASCII guardian. Use the existing local Cinzel face for
major display headings, system sans-serif for reading, and Sometype Mono for code
and compact metadata. Existing VT323 remains a small signature, not body copy.

## Palette

Dark bronze canvas, warm pale text, amber actions, green successful receipts,
red failed receipts. Tinted OKLCH neutrals; subdued text must remain readable.
Status text always accompanies color. The chat uses the platform's native theme.

## Structure

Clear navigation, a compact hero, an interactive workflow demonstration and a
sequence of readable sections. Preserve existing routes, installation links and
the browser policy demonstration. Prefer rows and timelines over repeated cards.

## Motion and interaction

Motion follows user action. The workflow preview is explicitly a simulation and
never sends work to a model or host. Respect reduced motion, support keyboard and
touch, and never hide the page behind a mandatory boot animation.

## Telegram

One updating activity message with a named state, measured duration, real tool
counts and a compact timeline. Emoji distinguish roles and outcomes. No percentage
completion or ETA is derived from the maximum allowed step budget.
