The others can do more.

That is not false modesty — it is the first line of this comparison. OpenClaw and Hermes have more channels, more skills, browser automation and mature cron fleets. If that breadth is what you are after, you are better served there — this page will not talk it away.

Talos trades breadth for something else: a deterministic policy kernel between model and effect, a sandbox around the shell, and a log whose integrity you can prove rather than have to believe. The gap between the two is doctrine, not backlog — and that is exactly what this page explains.

§1 · where the others lead

What OpenClaw and Hermes do better

The other side first, complete and without gloating. Anyone running either project should find nothing missing here that they use every day.

  • Channels. WhatsApp in both directions, several messengers, media pipelines for images, audio and documents. Talos has three ways in (Telegram, mail, CLI) — and all three only fetch.
  • Skills and plugins. Catalogues in the hundreds, from calendars to image generation, plus sub-agents and MCP integration. Talos has 21 tools, and the number grows slowly — on purpose, see §3.
  • Browser automation. Filling in forms, clicking, driving entire flows. The Talos browser renders and reads. Nothing more.
  • Everyday automation. Cron fleets, watchdogs, morning reports — both projects have matured here. Talos can run schedules, but runs them under a hard ceiling (§3).
  • Model routing. Multiple sources, local models, mature fallback chains. Talos has provider routes with fallback — solid, but narrower.

And structurally: both projects move faster, because a new capability there is a feature question. Here it is a kernel question — every new tool needs a verdict that survives 173 adversarial cases.

§3 · why deliberately less

Every missing row has a reason

None of this is backlog. Every entry was considered, rejected, and the boundary next to it is held by a red-team case. Whoever “retrofits” one of these rows is not building Talos plus a feature — they are building a different product.

inbound webhook Every way in fetches: Telegram long-polls, mail is pulled over IMAP. A webhook needs a port the world can reach — an outbound-only process would become a reachable one. That is why WhatsApp inbound does not exist, and poll() returns empty there. Deliberate, not “not built yet”.
browser automation Clicking, typing and submitting have no derivable target — the kernel could not judge what is about to happen. A tool without a target is DENY by construction. So browse renders and reads, inside the resolver cage, so that even a redirect cannot leave the host that was checked.
skill catalogue Breadth is cheap — gated breadth is not. Every tool needs a declared effect and a target extractor, otherwise there is nothing to judge. The 21 tools are the ones where the kernel can justify every verdict; tool number 21 had to pass the same test.
yolo mode The autonomy dial can only ever tighten, never widen. A mode that grants rights next to the kernel would be a second source of permission — exactly the problem capability tokens were built to remove.
plan approval Approving a plan would mean approving actions nobody has seen. A plan may set an order and an abort condition; every step still passes the gate on its own. A plan can only end a run earlier, never allow anything.
cron fleet Unattended means: NEEDS_HUMAN becomes DENY. A question dropped into a chat where a different conversation is going on is the most reliable way to land a “yes” on the wrong thing. That is why the schedule list looks short — it runs under the ceiling, not above it.

The short version: the model proposes, it never decides. Everything that would soften that order — a second path to rights, a channel that receives, a tool without a verdict — is not missing, it was rejected. Feature parity with OpenClaw or Hermes is explicitly not a goal.

§5 · which agent for what

The honest recommendation

OpenClaw or Hermes,

if an agent is meant to carry your day-to-day: messengers in both directions, browser flows, a broad skill catalogue, automation around the clock. That breadth is real, it has matured, and Talos will not offer it.

Talos,

if an agent gets a shell on a machine where something can break — and it must be provable afterwards what it did and what it did not. Kernel, sandbox, hash chain: that is what it is built for, and for little else.

No contradiction

Running both at once is not a style break but the obvious division: the broad agent for the work, the narrow one for the machine you hand a shell to. This comparison is meant to sharpen the choice, not replace it.
